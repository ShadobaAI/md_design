# Разметка md_design

Основа: md_design 0.15.1, commit `45e130f14970367c6e38deca937f61eb896ee6db` из https://github.com/crimsongoldteam/md_design. Это самостоятельный DSL, а не обычный Markdown: не оборачивай готовый `.md` в блок кода, не добавляй пояснительные заголовки/списки.

## Форма, надписи, команды

```text
--- Заказ покупателя ---
< Записать и закрыть {КнопкаПоУмолчанию = Истина} | Записать | Отмена >
Данные покупателя
```

Заголовок формы первым. Строка без специальных конструкций — надпись. Команды заключены в `< ... >`, разделены `|`. Для подменю применяется многострочная запись с точками уровня:

```text
< Записать | Еще
Еще
. Печать
. История >
```

Бизнес-команды кликабельны, но не выполняют действий над данными. Вложенные меню раскрываются. Иконки `@ИмяКартинки` понимает парсер, но библиотека картинок 1С не входит в этот пакет: renderer сообщает ограничение.

## Поля, флажки, переключатели

```text
Номер: 000001 {Тип = Строка(9)} & Дата: 18.09.2026
Организация: ООО Север__ВХ
Склад: Основной__С
Сумма: 1200.50 {Тип = Число(15, 2)}
[X] Активен
[ ] Пометка
Вид: (X)Юридическое лицо ( )Физическое лицо
Комментарий: Первая строка
_____________
_____________
```

`Заголовок: Значение`; пустое значение допустимо. Тип определяется по значению; идентификаторы с ведущими нулями задай строкой. Даты `дд.мм.гггг`, время `чч:мм[:сс]`, число с точкой/запятой. Строки `___` сразу после поля включают многострочный режим. `&` располагает элементы в одной строке.

Модификаторы после `__`: `В` выбор, `С` список, `Х` очистка, `О` открытие, `Д` регулирование. Применяются кириллические буквы. В макете выбор/список/открытие дают локальное окно ввода значения, календарь — выбор даты, регулирование увеличивает числовое значение на единицу. Это демонстрационное взаимодействие без справочников и серверных обработчиков.

## Группы и страницы

```text
###Реквизиты
  Номер: 001
  Дата: 18.09.2026

#Левая колонка #Правая колонка
  Имя: Иван    +Город: Москва
  Телефон: 123 +Почта: info@example.test

/Основное
  [X] Использовать
/Дополнительно
  Комментарий:
```

Отступы существенны. Для дочерних элементов используй единообразно два пробела; группа или страница без отступа завершает предыдущую вложенность. Вертикальные группы в одной строке заголовков образуют горизонтальную группу; `+` разделяет их содержимое по колонкам. `&` проще для нескольких полей одной строки.

`#` группа без выделения, `##` слабое, `###` обычное, `####` сильное, `#####` сворачиваемая, `######` всплывающая. В предпросмотре всплывающая группа приближённо представлена раскрываемой секцией. `/Название` — страница, вложенные страницы допустимы. Вкладки переключаются мышью и клавишами стрелок/Home/End.

## Таблицы

```text
| Товар | Количество | Цена |
| --- | ---: | ---: |
| Стол | 2 | 15000 |
| Стул | 4 | 3000 |
```

Вторая строка — обязательные разделители заголовков. `:---`, `:---:`, `---:` задают выравнивание. В строках допустимы `[X]` и `[ ]`, вложенность дерева обозначается точками в начале строки:

```text
| Наименование | Значение |
| --- | --- |
| Группа | |
| . Дочерняя строка | 10 |
```

Многоуровневые заголовки:

```text
| -Данные- ||
| Код | Наименование |
| --- | --- |
| 001 | Пример |
```

Ячейки редактируются локально. Дерево отображается с отступами, без сворачивания узлов. Многоуровневые строки отображаются с объединением ячеек; сложную вложенность проверяй визуально.

## Свойства и ограничения синтаксиса

Свойства: `{Имя = Значение; Другое = Значение}`, разделитель `;`. Тип может содержать параметры и список вариантов: `{Тип = Строка(100), Число(15, 2)}`. Проверенные свойства взаимодействия: `Видимость = Ложь`, `Доступность = Ложь`, `ТолькоПросмотр = Истина`, `КнопкаПоУмолчанию = Истина`. Renderer нормализует булевы значения, поскольку явные свойства upstream возвращает строками, а модификаторы — boolean.

Выравнивание DSL: `-> Справа`, `-> По центру <-`. Растяжение и платформенные размеры не равны CSS-пикселям. Не обещай точную ширину по числу подчёркиваний/пробелов.

`# / + & | < > { } _` имеют структурный смысл. Не считай кавычки механизмом экранирования: его здесь нет. Особенно проверь телефон с `+`, URL с `/`, текст с `&`, подчёркиванием и вертикальной чертой: они могут изменить дерево при формально успешном разборе. Не заменяй важный текст молча; сначала проверь дерево и макет, затем согласуй/обозначь приближение.

В адаптере расширен текстовый токен для кавычек и типографской пунктуации, которые upstream молча терял; грамматика структуры не менялась. При переносе такого текста в исходный upstream сохранность этих символов не гарантируется. Неизвестные символы и ошибки разбора теперь останавливают проверку с диагностикой.

Рабочие примеры: [поступление](../prototypes/order.md), [карточка контрагента](../prototypes/counterparty.md). После любого изменения запусти `--check`, затем осмотри форму и прочитай `data-warnings`.


## Цвета и образцы в таблице

`ЦветФона` и `ЦветТекста` принимают `#RRGGBB` или поддерживаемые названия (например, `Коралловый`, `Зеленый`). Для точного цвета используй hex. Эти свойства работают также на ячейках таблицы; `ТолькоПросмотр = Истина` можно задать отдельной ячейке.

Для воспроизведения цветовых зон добавлено **локальное свойство playground** `ЦветОбразца`. Это расширение визуализации в обычном синтаксисе свойств md_design, **не API/свойство платформы 1С**. Оно рисует редактируемый цветовой образец рядом с текстом ячейки:

```text
| Цвет |
| --- |
| Бордовый {ЦветОбразца = #b65b6a} |
```

В исходном upstream свойство может сохраниться в описании, но визуализация образца не поддерживается. Пример: [ценовые зоны](../prototypes/pricing-zones.md). Ввод границ в нём демонстрационный; автоматические расчёты из подписи не исполняются. Для календаря у даты укажи `__В`; без модификатора отображается обычное поле ввода.
