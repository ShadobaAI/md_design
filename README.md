# Накидка — прототипы форм 1С

Плагин Codex для создания интерактивных прототипов форм 1С по тексту, скриншоту или XML. Основан на [crimsongoldteam/md_design](https://github.com/crimsongoldteam/md_design).

Codex сохраняет описание формы в `.md` и открывает её во встроенном браузере. Поля, флажки, вкладки, меню и таблицы работают локально. Ввод в браузере не сохраняется; бизнес-команды 1С не исполняются.

## Установка

Для работы нужны **Codex** и **Node.js 22+** в PATH. Проверь `node --version`; установить Node.js можно с [официального сайта](https://nodejs.org/en/download). После установки Node.js перезапусти Codex.

Добавь [репозиторий](https://github.com/ShadobaAI/md_design) как Git marketplace в управлении плагинами Codex и установи **Накидку** из ветки `main`. Затем начни новый чат. Через Codex CLI это можно сделать так:

```powershell
codex plugin marketplace add ShadobaAI/md_design
codex plugin add md-design@shadobaai-md-design
```

Устанавливается готовый пакет. Пользователю не нужны npm, Python, исходный checkout или база 1С.

Формат плагина и marketplace описан в [официальной документации OpenAI](https://developers.openai.com/plugins/build/plugins).

## Использование

После установки и включения плагина Codex может автоматически выбрать **Накидку** по описанию задачи; явно указывать плагин каждый раз не требуется.

```text
Создай форму поступления: номер, дата, контрагент, склад
и таблица с товаром, количеством и ценой. Открой форму во встроенном браузере.
```

Для явного выбора добавь «Используй плагин Накидка» либо выбери его в интерфейсе Codex. Автоматический выбор зависит от формулировки; подробнее — в [документации о навыках](https://learn.chatgpt.com/docs/build-skills).

Можно приложить скриншот или XML формы, попросить изменить существующий прототип либо открыть универсальный пример `showcase`: [исходник](prototypes/showcase.md), [перечень возможностей](skills/md-design/references/showcase.md).

Codex создаёт `.md` в рабочем проекте пользователя. Чтобы сохранить изменение, попроси изменить этот файл: браузерные значения сбрасываются при перезагрузке. Предпросмотр работает без интернета, пока запущен его локальный процесс.

Если форма перестала открываться, попроси заново запустить предпросмотр. Ошибки разбора исправляются до открытия. Неподдержанные свойства доступны в `#preview[data-warnings]`; успешный разбор не заменяет визуальную проверку.

## Обновление и удаление

Чтобы получить новую версию **Накидки**, выполни:

```powershell
codex plugin marketplace upgrade shadobaai-md-design
```

Затем перезапусти Codex и начни новый чат.

Для удаления останови предпросмотры и удали **Накидку** через управление плагинами. Пользовательские `.md` остаются в рабочих проектах.

## CI и публикация

[build-plugin.yml](.github/workflows/build-plugin.yml) запускается только:

- при отправке стабильного тега версии, например `1.0.0`;
- на pull request — для проверки того же пакета, без публикации.

Обычный push ветки не запускает CI. Версии имеют формат `MAJOR.MINOR.PATCH`, без префикса, ведущих нулей и суффиксов. Тег обязан точно совпадать с версиями `package.json`, `package-lock.json` и `.codex-plugin/plugin.json`; контракт проверяется до установки зависимостей.

Конвейер выполняет `npm ci`, audit, typecheck, сборку, тесты визуализации/HTTP и тесты упаковки. JS минифицирован, source maps не создаются и не входят в пакет. Пакет проверяется без npm-зависимостей на Ubuntu и Windows с Node.js 22 и 24. Публикация ждёт успешного завершения всей матрицы.

В артефакте `md-design-plugin` находятся:

- `md-design-<версия>.zip` — готовый плагин;
- `md-design-<версия>-marketplace.zip` — тот же пакет с каталогом marketplace;
- `SHA256SUMS` — контрольные суммы обоих ZIP.

Артефакты Actions хранятся 14 дней. Опубликованный пакет остаётся в `main` и доступен независимо от срока хранения артефактов.

Для релиза:

1. Сначала отправь исходники и оба workflow в `main`.
2. Согласуй версию в трёх манифестах. Создай и отправь тег на этом коммите:

   ```powershell
   git tag 1.0.0
   git push origin 1.0.0
   ```

3. Дождись успешных **Build md-design plugin** и **Publish md-design marketplace**. Публикация стартует автоматически через `workflow_run`; ID сборки передаётся без ручного ввода.
4. Готовый пакет `plugins/md-design` и `.agents/plugins/marketplace.json` появятся одним коммитом в `main`. Каталог станет доступен для установки плагина (`AVAILABLE`). До первой публикации он помечен `NOT_AVAILABLE`, поскольку runtime ещё не добавлен.

[publish-marketplace.yml](.github/workflows/publish-marketplace.yml) использует правила из основной ветки и встроенный `GITHUB_TOKEN`. Право `contents: write` запрашивается только публикационной job; глобальные права можно оставить read-only. Правила `main` должны разрешать её push. Дополнительные secrets/PAT не нужны.

Перед публикацией проверяются источник workflow, репозиторий, успешность всего прогона, версия, commit, SHA-256, соответствие двух ZIP и безопасные пути файлов. Фактический тег должен по-прежнему указывать на собранный commit из `main`. Неполные сборки, сборки с незакоммиченными изменениями, prerelease, PR, несоответствующие теги и откат версии отклоняются. Код из скачанного пакета с write-токеном не исполняется.

Публикации идут последовательно с очередью; force push не используется. Повторная публикация того же commit и версии ничего не меняет. При сбое можно повторить публикационный workflow либо вручную запустить **Run workflow** с `build_run_id` успешной сборки тега.

## Разработка

Разработчику нужны Node.js 22+, npm и Python 3.12+. Python-скрипты используют стандартную библиотеку.

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd test
python -m unittest discover -s tests -p "test_*.py"
npm.cmd run package:plugin
npm.cmd run check:plugin
```

Локальный marketplace находится в `.build/marketplace`. Сборка очищает корневой `dist`, упаковка пересоздаёт только `.build` и включает явный список файлов. Чистота исходников и commit записываются в metadata пакета; незакоммиченные локальные пакеты не публикуются.

Ручная проверка и запуск предпросмотра из исходников:

```powershell
node scripts/preview.mjs --file prototypes/order.md --check
node scripts/preview.mjs --file prototypes/order.md --background
```

Запуск возвращает `url`, `pid`, `file`. Открывай URL целиком, включая случайный путь. Сервер слушает только `127.0.0.1`, отдаёт выбранный файл и разрешённые статические ресурсы, проверяет Host/Origin и не принимает запись через HTTP. Останавливай только PID своего предпросмотра.

## Происхождение и ограничения

В `vendor/md_design` сохранена минимальная часть upstream-парсера с [лицензией MIT](vendor/md_design/LICENSE.md). Закреплённый commit, список файлов и собственные исправления указаны в [UPSTREAM.json](vendor/UPSTREAM.json). Лицензии включённых npm-компонентов автоматически собираются в `dist/THIRD_PARTY.md` и входят в плагин. Сторонний checkout для сборки не нужен.

Это браузерный прототип, а не движок платформы 1С. Поддерживаются группы, страницы, поля, флажки, переключатели, меню, таблицы с деревом строк и составными заголовками. Всплывающие группы показаны раскрываемыми секциями; библиотека картинок и обработчики 1С не эмулируются.
