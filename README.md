# Накидка — прототипы форм 1С

Плагин Codex для создания интерактивных прототипов форм 1С по тексту, скриншоту или XML. Основан на [crimsongoldteam/md_design](https://github.com/crimsongoldteam/md_design).

Codex сохраняет описание формы в `.md` и открывает её во встроенном браузере. Поля, флажки, вкладки, меню и таблицы работают локально. Ввод в браузере не сохраняется; бизнес-команды 1С не исполняются.

## Установка

1. **Подготовь Codex.** Используй настольное приложение со встроенным браузером. Установи **Node.js 22 или новее** с [официального сайта](https://nodejs.org/en/download), если он ещё не установлен, и перезапусти Codex.
2. **Добавь магазин.** В Codex открой **Plugins (Плагины)** и выбери добавление магазина (marketplace). Вставь ссылку на [магазин Накидки](https://github.com/ShadobaAI/md_design-mkt): `https://github.com/ShadobaAI/md_design-mkt`.
3. **Установи плагин.** В добавленном магазине найди **Накидку**, открой её карточку и нажми кнопку установки. Убедись, что плагин включён.
4. **Разреши проверку в браузере.** Открой **Settings → Browser → Agent permissions**. Добавь исключение для `http://127.0.0.1:18765` без пути после порта. Для **Browse** выбери **Always allow**. Это стандартный адрес предпросмотра Накидки.
5. **Начни новый чат.** Попроси Codex: «Создай простую форму 1С и открой её во встроенном браузере». Если появится дополнительный запрос доступа к странице, подтверди его.

Если разрешения браузера заблокированы организацией, попроси администратора разрешить адрес предпросмотра. [Подробнее о разрешениях](https://learn.chatgpt.com/docs/reference/settings#browser).

## Использование

Опиши нужную форму обычными словами. Например:

```text
Создай форму поступления: номер, дата, контрагент, склад
и таблица с товаром, количеством и ценой. Открой форму во встроенном браузере.
```

Codex может выбрать Накидку автоматически. Для явного выбора добавь к запросу «Используй плагин Накидка».

Можно приложить скриншот или XML формы, попросить изменить готовый прототип или показать пример со всеми возможностями: «Открой пример showcase из плагина Накидка».

Форма сохраняется в файл `.md` в папке проекта. Чтобы изменить её, напиши Codex, что нужно исправить. Введённые вручную значения в браузере сбрасываются при перезагрузке; сохранить их можно, попросив Codex внести их в файл формы.

Если форма перестала открываться, попроси Codex заново запустить предпросмотр. Если порт занят, попроси сменить его в настройках Накидки, например на `18766`, и разреши новый адрес в настройках браузера по шагу 4 установки.

## Обновление

1. Открой новый чат в Codex и отправь этот запрос:

   ```text
   Обнови плагин Накидка: выполни команду
   codex plugin marketplace upgrade shadobaai-md-design
   ```

2. Подтверди выполнение команды, если Codex запросит разрешение, и дождись сообщения об успешном обновлении.
3. Перезапусти Codex и начни новый чат — в нём будет доступна обновлённая Накидка. Сохранённые формы и настройки порта останутся на месте.

## Удаление

Попроси Codex остановить открытые предпросмотры. Затем открой **Plugins (Плагины)**, найди **Накидку** и удали её. Сохранённые файлы форм останутся в папках проектов.

## Для разработчиков

### Настройки плагина

Пользовательские настройки находятся в `%USERPROFILE%\.codex\md-design\config.json` (на macOS/Linux — `~/.codex/md-design/config.json`). Если задан `CODEX_HOME`, используется `<CODEX_HOME>/md-design/config.json`:

```json
{
  "port": 18765
}
```

Файл можно создать или отредактировать вручную. Он сохраняется при обновлении плагина и применяется при следующем запуске предпросмотра. Значение по умолчанию задаётся в [settings.json](settings.json). Порт — целое число от `0` до `65535`; `0` выбирает свободный порт. Для разового запуска `--port <номер>` переопределяет настройку файла. После смены порта нужно обновить адрес в разрешениях браузера.

### CI и публикация

[build-plugin.yml](.github/workflows/build-plugin.yml) запускается только:

- при отправке стабильного тега версии, например `0.1.0`;
- на pull request — для проверки того же пакета, без публикации.

Обычный push ветки не запускает CI. Версии имеют формат `MAJOR.MINOR.PATCH`, без префикса, ведущих нулей и суффиксов. Единственный источник версии релиза — Git-тег. При упаковке CI записывает его в манифест готового плагина, метаданные и имена ZIP; в исходных манифестах версия проекта не хранится. Формат тега проверяется до установки зависимостей. На pull request пакет проверяется с наибольшей версией из тегов в истории коммита, без публикации.

Конвейер выполняет `npm ci`, audit, typecheck, сборку, тесты визуализации/HTTP и тесты упаковки. JS минифицирован, source maps не создаются и не входят в пакет. Пакет проверяется без npm-зависимостей на Ubuntu и Windows с Node.js 22 и 24. Публикация ждёт успешного завершения всей матрицы.

В артефакте `md-design-plugin` находятся:

- `md-design-<версия>.zip` — готовый плагин;
- `md-design-<версия>-marketplace.zip` — тот же пакет с каталогом marketplace;
- `SHA256SUMS` — контрольные суммы обоих ZIP.

Артефакты Actions хранятся 14 дней. Опубликованный пакет остаётся в ветке `main` репозитория [md_design-mkt](https://github.com/ShadobaAI/md_design-mkt) и доступен независимо от срока хранения артефактов. CI не делает push в репозиторий исходников `md_design`.

Перед первой публикацией настрой доступ:

1. Создай fine-grained personal access token с доступом **только к `ShadobaAI/md_design-mkt`** и разрешением **Contents: Read and write**.
2. В репозитории `ShadobaAI/md_design` добавь его как Actions secret **`MARKETPLACE_TOKEN`**: **Settings → Secrets and variables → Actions → New repository secret**.
3. Правила ветки `main` в `md_design-mkt` должны разрешать push владельцу токена. Пустой репозиторий CI инициализирует при первой публикации; вручную создавать в нём файлы не нужно.

Для релиза:

1. Сначала отправь исходники и оба workflow в `main`.
2. Создай и отправь тег нужной версии на этом коммите:

   ```powershell
   git tag 0.1.0
   git push origin 0.1.0
   ```

3. Дождись успешных **Build md-design plugin** и **Publish md-design marketplace**. Публикация стартует автоматически через `workflow_run`; ID сборки передаётся без ручного ввода.
4. Готовый пакет `plugins/md-design` и `.agents/plugins/marketplace.json` появятся одним коммитом в `main` репозитория `md_design-mkt`. Каталог будет доступен для установки плагина (`AVAILABLE`). Файл `.agents/plugins/marketplace.json` в исходниках служит шаблоном для упаковки; пользователи устанавливают плагин из `md_design-mkt`.

[publish-marketplace.yml](.github/workflows/publish-marketplace.yml) использует правила из `main` репозитория исходников. Встроенный `GITHUB_TOKEN` имеет только права чтения исходников и артефактов. Для записи в отдельный marketplace используется `MARKETPLACE_TOKEN`: встроенный токен [ограничен репозиторием своего workflow](https://docs.github.com/en/actions/concepts/security/github_token).

Перед публикацией проверяются источник workflow, репозиторий, успешность всего прогона, версия, commit, SHA-256, соответствие двух ZIP и безопасные пути файлов. Фактический тег должен по-прежнему указывать на собранный commit из `main` репозитория исходников. История версий также проверяется по исходникам, отдельно от истории коммитов marketplace. Неполные сборки, сборки с незакоммиченными изменениями, prerelease, PR, несоответствующие теги и откат версии отклоняются. Код из скачанного пакета с write-токеном не исполняется.

Публикации идут последовательно с очередью; force push не используется. Повторная публикация того же commit и версии ничего не меняет. При сбое можно повторить публикационный workflow либо вручную запустить **Run workflow** с `build_run_id` успешной сборки тега.

### Локальная разработка

Разработчику нужны Node.js 22+, npm и Python 3.12+. Python-скрипты используют стандартную библиотеку.

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd test
python -m unittest discover -s tests -p "test_*.py"
npm.cmd run package:plugin -- --version 0.1.0
npm.cmd run check:plugin
```

Локальный marketplace находится в `.build/marketplace`. Параметр `--version` задаёт версию только для локальной проверки; без него используется наибольшая версия из тегов в истории коммита. В CI релиза версия всегда берётся из запускающего тега. Сборка очищает корневой `dist`, упаковка пересоздаёт только `.build` и включает явный список файлов. Чистота исходников и commit записываются в metadata пакета; незакоммиченные локальные пакеты не публикуются.

Ручная проверка и запуск предпросмотра из исходников:

```powershell
node scripts/preview.mjs --file prototypes/order.md --check
node scripts/preview.mjs --file prototypes/order.md --background
```

Запуск возвращает `url`, `pid`, `file`. Открывай URL целиком, включая случайный путь. Сервер слушает только `127.0.0.1`, отдаёт выбранный файл и разрешённые статические ресурсы, проверяет Host/Origin и не принимает запись через HTTP. Останавливай только PID своего предпросмотра.

Неподдержанные свойства доступны в `#preview[data-warnings]`. Успешный разбор не заменяет визуальную проверку. Всплывающие группы показаны раскрываемыми секциями; библиотека картинок и обработчики 1С не эмулируются.

### Происхождение

В `vendor/md_design` сохранена минимальная часть upstream-парсера с [лицензией MIT](vendor/md_design/LICENSE.md). Закреплённый commit, список файлов и собственные исправления указаны в [UPSTREAM.json](vendor/UPSTREAM.json). Лицензии включённых npm-компонентов автоматически собираются в `dist/THIRD_PARTY.md` и входят в плагин. Сторонний checkout для сборки не нужен.

Подробнее: [синтаксис](skills/md-design/references/syntax.md), [восстановление из скриншотов/XML](skills/md-design/references/reconstruction.md), [возможности предпросмотра](skills/md-design/references/showcase.md).

## Лицензия

Собственные дополнения Накидки распространяются под [Mozilla Public License 2.0](LICENSE). Плагин можно бесплатно использовать, в том числе в коммерческих проектах.

Лицензия относится к самому плагину: его коду, навыку и документации. Созданные с его помощью формы и пользовательские данные автоматически под MPL не подпадают; скопированные из плагина материалы сохраняют свои лицензии.

При распространении изменённых файлов, покрытых MPL, предоставляй их исходники под MPL 2.0 и сохраняй сведения об авторах. Если распространяешь готовую сборку, сообщи получателям, где получить исходники покрытых MPL компонентов этой версии. Лицензия не требует публиковать внутренние изменения, которые ты не распространяешь.

Исходный код md_design сохраняет [лицензию MIT](vendor/md_design/LICENSE.md), а сторонние компоненты — свои лицензии.
